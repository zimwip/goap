# ADR 0163 — The graph service in Rust, behind a comparing proxy

**Status**: accepted; phase 1 implemented (the workspace, the store, the proxy, the perf targets), phase 2 implemented (the reads of the bench, the shadow mode), phase 3 implemented (the writes of the bench), phase 4 implemented (every method, the bootstrap, the content graph; the compose stack runs the Rust service) · **Date**: 2026-10

## Context

The graph service carries the load of the platform: every change, every commit and every read of a view goes through
it. The performance phases shaped it with a set of choices, each measured by `make perf`:

- **What a commit reads.** A baseline stores only its header; its state is a selection of the last commit of each node
  on its branch up to its order (ADR 0140, 0143). A commit and a merge read only the nodes they touch, in batches
  (ADR 0137 and addendum: `prefetch`, `BaselineVersions`, `LinkSetsOf`). The N+1 reads of a page are batched
  (`NodesAt`, change heads).
- **Links.** A version's links are a link set held as skip deltas of depth at most 16 (ADR 0141), written in batches
  of a thousand; a navigation hop reads its link types only, entering links by source.
- **Reads.** A request that only reads runs on a read-only pool, with no `BEGIN` / `COMMIT` on PostgreSQL, and runs
  again on the writer when it meets a write (SQLSTATE 25006, SQLITE_READONLY). `GetNode` answers a page of links.
- **Changes.** A change is a fold of its log (ADR 0153), its impact events carrying what they change (ADR 0142), one
  log entry per review or landing (ADR 0144); positions travel as watermarks (`X-Goap-Change-Seq`,
  `X-Goap-At-Least`).
- **Caches.** One bounded cache kind (ADR 0156): drafts 64 MiB, version links 32 MiB, headers 4 MiB, validations
  16 MiB, five minutes without a read.
- **Writers.** The writers of a tree of changes are serialized by an advisory lock on its root, then the branch lock
  (ADR 0127); the guardians judge in the transaction of the commit (ADR 0140).
- **Contracts.** Every read names its view (ADR 0157), reach filters it (ADR 0161), events leave through an outbox
  (ADR 0136).

Go reached the point where the remaining costs are the allocations of the folds and the decoding of the rows. Rust
removes the garbage collector from the hot paths and lets the type system carry invariants the Go code checks at run
time. The rewrite must not be a translation: only the behaviour of the RPCs and endpoints must stay the same.

## Decision

1. **A Cargo workspace beside the Go modules**, `rust/` (not in the `go.work`), generated from the same `proto/`:
   - `goap-proto`: the messages (prost, with pbjson for the protobuf JSON form) and per service a table of its methods,
     a server trait whose every method answers `unimplemented` by default, its router and its client, generated by
     `build.rs` with protox (no `protoc`); the descriptor set is exposed for the proxy.
   - `goap-connect`, `goap-ctx`: the Connect protocol (unary and server streaming, proto and JSON codecs, the error
     model, interceptors) over axum and reqwest.
   - `graph-store`: PostgreSQL (tokio-postgres, deadpool) or SQLite (rusqlite, compiled in: the one C of the build).
     Both keep a writer and a pool of read-only connections; `StoreError::is_read_only` sends a read that met a write
     to the writer. The migrations are the Go services' own files (graph, domain registry, smart tags), embedded and
     recorded in the same `schema_migrations` table (PostgreSQL by name under the advisory lock of the schema, SQLite
     by component and name), so either service starts on a database the other wrote.
   - `graph-service`: the binary `goap-graph-rs`, serving `GraphService`, `DomainService`, `SmartTagService` and
     `ImportService` with the environment of the Go service (`GOAP_HTTP_ADDR`, `GOAP_DB_DSN`, else
     `GOAP_SQLITE_PATH`, else a database in memory), `/healthz` and `/readyz`.
   - `goap-proxy` (below).
   The pure core (`graph-core`: views, folds, selection, link sets, the guard's obligations) comes with phase 2, free
   of I/O; the store is a trait per dialect with the SQL text of each, a reader and a write transaction as distinct
   types (a write cannot be asked of a reader), the tree lock a token the write operations take, the caches `moka`
   with the bounds of ADR 0156, the impact events one enum serialized to the bytes Go writes.
   Cypher reuses an existing parser (`decypher`, else `uni-cypher`); the scripts of the domains run on `boa` (no C)
   behind a `ScriptEngine` trait, a precompiled path (QuickJS as WebAssembly) left for later.
2. **A proxy in front of the graph services, deployed on its own**: `goap-proxy`, a Connect proxy that reads any method
   of `proto/` through the descriptors (no code per method). `GOAP_PROXY_MODE`:
   - `go`, `rust`: every call to one service, bytes passed as they are;
   - `split`: every call to the Rust service, replayed on the Go one when it answers `unimplemented` (HTTP 501, or a
     route it does not know): the two share one database. `/proxy/coverage` lists the methods called, who served them
     and those that still fall back; `POST /proxy/probe` asks the Rust service each method of the four services with
     an empty request (a test or perf environment only);
   - `compare`: every call to the Go service, which answers the client, and to the Rust one, each on its own database,
     one call at a time. Each side allocates its own UUIDs, so the proxy pairs the ids found at the same place of the
     two answers (lists matched by what their elements hold once the unknown ids and the times are blanked, map keys
     that are ids likewise; a short id, the eight first digits of a UUID as in `change-3013a15b`, follows its UUID),
     writes the Go ids of the next requests (body and headers) as their Rust twins, reads the Rust answer back in Go
     ids, masks the times and the fields of `GOAP_PROXY_IGNORE`, and gives a verdict: `same`, `order_differs`,
     `message_differs` (the soft ones), `differs`, `error_differs`, `undecodable`, `rust_unimplemented`. Every call is
     a line of `calls.jsonl` (verdict, both durations, differences, the ids that clash with an earlier pair, the bodies
     of a divergent call) in `GOAP_PROXY_REPORT_DIR`; `/proxy/report` writes `summary.json` and `ids.json`.
   - `shadow`: every call to the Go service, which answers the client; a call that only reads (the Go rule of
     `ReadOnlyRequests`: `Get…`, `List…`, `Export…`, `Diff…`, `Search…`, `Compare…`, `Is…`, `Query…`, a stream
     left out) goes to the Rust one too, both on one database, one call at a time: the Rust reads are judged against
     what the Go service wrote before the Rust service writes anything. No id to pair: the verdicts and the report
     are those of `compare`.
   - `goap-proxy diff-db --go <dsn> --rust <dsn> --ids ids.json` compares the tables of the two databases as
     multisets, once the ids are paired (the comparison's, then the rows one of a kind on each side) and the times
     masked.
   `/metrics` counts the calls per method and who served them (`goap_proxy_calls_total{service,method,served_by}`),
   the verdicts and the time of each side.
3. **The performance stack goes through the proxy.** `make perf` (mode go, `PERF_PROXY=0` without it), `make
   perf-rust` (`deploy/compose/perf.rust.yml`, mode `PERF_RUST_MODE`: split until the Rust service serves every
   method, then rust), `make perf-diff` (mode `PERF_DIFF_MODE`: `shadow` while the Rust service only reads, both on
   the schema `graph`; `compare` once it writes: both schemas dropped, the Go service on `graph`, the Rust one on
   `graph_rs`, then `diff-db`; goap-bench serial and seeded, then the report; `PERF_DIFF_RUST=go` compares Go with
   Go).
   Each Rust binary has its image: `goap/rust:dev` (`docker build --target rust`) the graph service, `goap/proxy:dev`
   (`--target proxy`) the proxy, a separate binary no crate of the service depends on.
4. **Phases, one pull request each**: (1) the workspace, the store and its migrations, the skeleton service, the
   proxy, the targets; (2) the reads (views, `GetNode`, neighbourhoods, baselines, listings, queries); (3) the writes
   of the bench (changes, impacts, review, commit, merge, rebase, the domain registry); (4) everything else, then the
   Go service and the split mode leave the stack. Each phase is done when `make perf-diff` finds no divergence on what
   it serves.

## Consequences

- The comparison is measured before it measures Rust: Go against Go (`PERF_DIFF_RUST=go`) on 939 calls of the bench in
  lifecycle mode gave no divergence and no clashing id, and `diff-db` found the fourteen tables of the two databases
  the same. Lists the graph orders by id come in another order on each side: `order_differs` is soft.
- Both services read and write one schema; a migration lands in the Go directories and the Rust service embeds it on
  its next build. `TestSchemasAligned` keeps the two dialects aligned as before.
- The Rust service holds the same multi-database option as the Go one (PostgreSQL, SQLite); the Go service goes away at
  the end of phase 4, the proxy stays as the entry of the performance stack and of later comparisons.
- Phase 2 (the reads). `graph-core` holds the reads as functions over a store trait (`store::ReadTx`, one statement
  or a few batched per method): the selection of a state (ADR 0143: the chain of forks, batches of 2000, the node
  list of the namespace for a whole state), the view of a branch, a node with its entering links from the version of
  each source the view holds, the neighbourhood (suspect links), the pages (links by type, nodes by type and text),
  the versions of a node, the headers of the changes and their pages (`changes_page`, `node_changes`), the lineage gap
  of two baselines and their difference (`lineage_gap`, `diff_baselines`). `graph-store` writes the SQL of both
  dialects once (`read/sql.rs`, as `sqlbuild.go`) and reads the rows into one value shape. `goap-graph-rs` serves
  `GetNode`, `ListNodeLinks`, `GetNodeNeighbourhood`, `ListBaselineNodes`, `ListNodeVersions`, `GetBranch`,
  `DiffBaselines`, `ListChanges` (headers) and `ListNodeChanges` for a platform service acting by itself (no reach);
  it answers `unimplemented`, so the Go service answers in mode split, a person or a service acting for one (the
  reach and the access snapshot of ADR 0161), a view of a change (the fold of its log, ADR 0153), a read at a log
  position (`X-Goap-At-Least`), the state of a change's branch, a change read whole, a unit or project named by its
  key (the structures of the catalogue). Those reads, `QueryView` (Cypher) and the other listings move to phases 3
  and 4.
- Measured in mode shadow, goap-bench serial and seeded: on PostgreSQL (lifecycle, 4000 versions) 1,528 reads of five
  node reads, then (commit, 5000 versions) 1,455 reads of the eight methods the bench reads with, all `same`
  (`ListNodeLinks`, which the bench never calls, is covered by the tests only); on SQLite (goap-dev
  and `goap-graph-rs` on one file, lifecycle, 2000 versions) 794 reads, all `same`. One fix came out of it: a float
  read from `jsonb` differed at its last digit until serde_json parsed floats correctly rounded (`float_roundtrip`),
  as Go does. The Rust service answered each read in less time than the Go one (GetNode p50 3.7 ms against 9.0 ms,
  GetBranch 1.1 against 6.6), a hint only: it reads second, after the Go service warmed the database's pages.
- Phase 3 (the writes of the bench). `graph-core` `write/` runs a write in one transaction of the store (`Tx`: the
  change logs folded once per change, the guard's obligations, the outbox, the positions the logs were left at for
  `X-Goap-Change-Seq`): `ImportDomain` (a new version a platform service imports, `graph-catalog` `imported`: the YAML
  read strictly, checked as `Domain.Validate` and the type catalogue check it, stored with Go's JSON of the definition
  and its `domain_outbox` event; a domain with issues, lifecycles, algorithms, validators, forms, documents or
  structures, a version already stored, or anything yaml.v3 reads more loosely is the Go service's), `CreateChange` / `DeleteChange`, the impact operations (create, checkout and its batch, update,
  link create / delete), `ImpactNodeReviewBatch` (the record of the review first, then every verdict in one entry
  naming it as its cause, ADR 0105), `CommitChange` (the versions, their link sets shared or as deltas, ADR 0141, one
  `committed` entry), `MergeChange` (a fast-forward), `CommitEdits` (the producer's path, all of it in one
  transaction), `ListDomains`, and `GetNode` / `ListNodeLinks` in the view of a change (its fork, its commits, its
  drafts). It serves the simple world: a platform service acting by itself, the main flow, a log of impact events and
  review records only, no sub-change, lifecycle, guardian, personal change, platform namespace, planned creation,
  URL target, domain running validators, revert, rebase or three-way merge, no dependency; anything else answers
  `unimplemented` with its transaction rolled back, and the split proxy replays it on Go. Measured in mode compare
  with Rust behind a split proxy (Go on the Rust schema for what it does not serve), goap-bench serial and seeded on
  PostgreSQL: lifecycle and commit (200 changes, new domain versions on the way) give no divergence and nothing falls
  back, the outbox events are the same but for the order of a baseline's `set` map, and `diff-db` finds the tables
  the same but for the order a link id decides (the `drafted` of a checkout, the order `CommitEdits` writes its edits
  in), which Go against Go shows as well.
  The proxy pairs the ids of two answers by place, and of two lists by what their elements hold; elements alike but
  for ids not paired yet (two new links between new nodes, each side in the order of its own ids) say nothing of
  which is which, so they are left unpaired, compared as ids, until an answer tells them apart (pairing them by
  position mispaired them half the time, and every call after diverged).
- Phase 4 (everything else), implemented. `SmartTagService` is served whole (`graph-service` `smarttags.rs`, the SQL in
  `graph-store` `read/smarttags.rs`: the times `timestamptz` on PostgreSQL, Go's RFC 3339 text on SQLite), for any
  caller, its errors worded as Go words them; the proxy pairs its ids (32 hex digits) like UUIDs. Driven through the
  compare proxy (create, share, update, list, get, delete, the refusals), every call is `same`, messages included.
  `GetDomain` answers the built-in domains (their YAML read as `def.ParseDomain` reads it) and the stored ones
  (`graph-service` `domainpb.rs`: the definition mapped onto `registry.v1.Domain` as `lib/domainpb` maps it);
  `ExportDomain` the JSON of a stored domain as Go writes it (the definition through YAML and back: empty lists
  written, empty `requires` and forms dropped, keys sorted, an indentation of two); the YAML
  export and the built-in domains are still Go's. Every built-in, `alm`, `code` and a bench domain, the unknown
  format and the missing domain: `same`. `ListTypes` resolves the catalogue of the domains in force (`Catalog::types` /
  `link_types`, the node validators of each type, a transition's `requires` and `children`). A platform service's
  `PublishDomain` (of a draft with nothing the Go service alone checks), `CreateDomainVersion` (the stored JSON under
  the new number, Go's text kept on SQLite) and `DeleteDomain` (a draft removed, a published version archived) write
  as the Go service does, with the event of each in `domain_outbox`. A scenario of 26 calls (each refusal included):
  every one `same`, served by Rust, the tables and the outbox of the registry the same. `SaveDomain` and
  `ValidateDomain` read the edited domain from the protocol as `DomainFromPB` does (`domainpb::imported`); a draft
  with issues stays Go's, which stores it and words them. Reading the definitions Go writes, a nil slice is a `null`

  `graph-core` `items`, `GetStructures`) and `ListNamespaces` are served for any identified caller, as Go serves them;
  but the first call of a person creates its user (Go's `EnsureCaller`), so a person the graph holds no user of yet
  is left to Go (`Graph::identified`), which creates it in the shared database. `GetChange` answers the whole
  change as `ChangeChecked` does (`graph-core` `write::whole`): the header, the impacts of the fold, the items of its

  (`valid`, the message, `modified` against the version checked out from); a draft with origins and a read at a

- A position of a change log not reached (`X-Goap-At-Least`, ADR 0153): refused as Go's `draftState` refuses it, its words and its `behind` reason (`Graph::reached`); Go refuses it on the reads that fold the change, Rust on every request naming one, which the web asks only of requests about that change. The changes filtered by a unit or a project named by its key (`ListChanges`, Go's `scopeFilter`: the URL of its structure, a URL that does not read kept as it is). Compared with Go's: the same answers.
- The head of the branch of a change as Go's `Graph.BranchHead` answers it (`read::any_branch_head`, Go's `changeBranchHead`: its fork, the order of its last commit, no id): `GetBranch` with its state (`read::branch_state`), `ExportGraph` and `StartGraphExport` of it (the empty snapshot, since it holds no baseline). Compared with Go's before and after a commit on the branch: the same answers.
- `AppendLog` of an entry naming a change the store does not hold: the lock of the change, then the insertion, as Go's guard does, so the refusal is Go's (`lock change …` for an id that is no UUID, the broken foreign key of `log entry …` for one no change has).
- `ProposeImpact` of an impact carrying reviews (refused in Go's words, the graph sets them) or flagged superseded (proposed so, as Go records it).
- A person's writes of the organisation: the rights on the projects judged at the commit as `access.ProjectScopeValidator` judges them (`write::validators` `Scope`, on the state before the commit: a platform Assignment a platform administrator's, a project's Assignment its administrators', its flags its owners', a new project the administrators' of its parent, a stop or a move the owners'), the caller given to the commit (`Env::person`, none for a platform service); and the writes of the platform's namespaces by a caller not administering the platform, judged by the same gates as any other (only the settings of those namespaces stay the Go service's).
- A person's writes of the domain registry (`SaveDomain`, `PublishDomain`, `CreateDomainVersion`, `DeleteDomain`, `ImportDomain`, `RunAlgorithm`): asked of the organisation's rules as Go's `Service.authorizeDomain` asks them (`Domains::authorize`: `write`, `publish` or `delete` on the resource `domain` `<name>@<version>`), at the same point of each call.
- A domain's YAML read as Go reads it (`ImportDomain`): `def.ParseDomain` is yaml.v3 with `KnownFields`, and a
  definition that does not read is refused in its words (`invalid domain: parse domain: yaml: …`). yaml.v3 is a Go port
  of libyaml, so the Rust service reads libyaml's events itself, through `unsafe-libyaml-norway` behind a safe parser
  (`crates/libyaml`, the one crate of the workspace allowed `unsafe`): the same scanner and parser give the same
  problems at the same marks, which no Rust YAML parser does. `graph-catalog` `yamlv3` composes the node tree as
  `parser.parse` does (tags shortened, scalars resolved by `resolve`, anchors, lines from 1; the two tokens yaml.v3's
  scanner reads ahead of its parser make a token past the document that does not scan fail too) and `decode` decodes it
  into the shape of `def.Domain` by `decoder.unmarshal`'s rules: a scalar's own text for a string (`version: 1.10` is
  `"1.10"`), the yes / no of YAML 1.1 for a bool, a float truncated for an int, the type errors gathered with their line,
  duplicate keys, merges, and the three types whose `UnmarshalYAML` takes a short form decoding an object by a decoder of
  their own, which checks no field (an unknown key in a node type is accepted, as in Go). The shape generated from the
  Go structs (`domain_shape.gen.json`, moved to `graph-catalog`) now carries the Go type of each value, JSON's
  `omitempty` and the field of each short form; the JSON stored is `json.Marshal`'s (the fields in their order, a nil
  pointer only left out, HTML characters escaped, its floats, a timestamp in RFC 3339). An import that replaces a draft
  or publishes it now writes through the same store as `SaveDomain` (`Domains::store`, Go's `SQLStore.SaveDomain`: a
  draft replaced keeping its creation, another status refused) and answers the version as stored. A domain whose JSON
  `json.Marshal` refuses (a mapping keyed by other than strings, a NaN among the values of an instance) is still Go's.
- The check of a domain's definition (`Domain.Validate`, `Schema.check`, `Service.validateDomain`): `graph-catalog`
  `validate`, every issue at Go's path in Go's words and order (names, extends and cycles, lifecycles and their
  `Lifecycle.Issues`, gate criteria, documents and child states, algorithms, instances and where they are plugged,
  search properties, enums and attributes, link types, structures, required links, creation forms, item types,
  importers). The forms follow `form.CheckForm` (`graph-catalog` `form`) over the registry of widgets as Go writes it
  for the web (`widgetCatalog.gen.ts`, read at build time, so a new widget reaches the Rust service with its
  catalogue). A CEL guard or criterion is judged by a type checker following cel-go's over the guard environment
  (`graph-script` `celcheck`: the variables, the operators, the macros as the parser expands them, the functions guards
  use; a corpus of expressions gives the same verdicts as `guard.Compile`); a script by QuickJS, with none of the syntax
  goja may read otherwise. What only Go words stays the Go service's: a guard or script its compilers may refuse, a
  parameter value its coercion refuses, a pattern its `regexp` refuses, a default checked in words of its own, a
  timestamp or an unsigned integer in a field of any type (which the JSON no longer carries as yaml.v3 decoded it). So
  `ImportDomain`, `SaveDomain`, `PublishDomain` and `ValidateDomain` serve every domain, `alm` and `code` included: a
  draft with issues stored with them, an import to publish with issues kept as a draft and refused with them
  (`invalid domain: cannot publish: …`), a publish of a draft with issues refused. The domain of a request is read as
  `domainpb.DomainFromPB` reads it (`domainpb::definition`: the lists Go leaves nil, the form `pbconv.FormFromPB`
  drops when it does not read) and written as `json.Marshal` writes `def.Domain` (`decode::from_json` over the shape,
  as `json.Unmarshal` reads it). A domain the domains in force would
  make no catalogue with gets the issue `Service.validateDomain` adds, in `typecat.New`'s words (`Catalog::new`).
  The JSON of every answer writes its doubles as protojson does (`goap-connect`'s formatter: `200`, not `200.0`,
  an exponent below 1e-6 or from 1e21 on), and an empty form or set of instance values is no field, as
  `pbconv.Struct` gives none.
- The relay of an outbox never kicks itself: a drain finding the relay at work only tells the one at work to look
  again (and that one looks again once it lets go, for a drain that came after its last look). Kicking `Relay::run`
  from there had it drain, find the relay busy and kick itself again without ever yielding its worker, which held the
  I/O driver: every request of the service then waited, its transaction left open (the service that "stops" under
  load).
- The router of the two graph spaces is Rust's (`route.rs`, Go's `graphsvc.Router`, ADR 0154 §9), a middleware in
  front of the graph service: with graph sources declared at the head of main of `platform` (read again when that
  head moves), a unary call naming a namespace another graph holds (its own or its view's) or a change that lives
  there (looked up by `GetChange` in each graph, as the caller, remembered) is forwarded as is, headers and body; one
  naming neither is served here, then tried in the other graphs while it is not found; `GetGraphOverview` and
  `ListNamespaces` merge every graph's answer, each namespace naming its source. The handler no longer leaves those
  calls to Go (`State::held`, `other_graphs` are gone).
  A change id the store cannot read is an error in its words, as Go's `HasChange` answers, and `ListNodeVersions`
  of an id PostgreSQL cannot read answers PostgreSQL's refusal, as Go's store passes it on (both were hidden by the
  fallback to Go). The scenario with a graph declared at an unreachable location: outbox and bus the same on both
  sides; what differs is the transport's words for the unreachable graph (Go's resolver, reqwest's), the lists ordered
  by ids each database draws (the PROV-O export, pages of links) and the cursors of the pages of changes.
- The refusals no longer left to Go. `QueryView`: the parser reads the constructs the subset refuses as the grammar
  reads them (UNION, WITH, the writes, UNWIND, list and pattern comprehensions, quantifiers, parameters, functions
  unknown or in a namespace, a query without MATCH) and, the whole query read, answers the refusal Go's build meets
  first, in its words and at its line and column (`cypher::parse::read`, `Error`); a `@` within a name is the
  grammar's lexer refusing it (`token recognition error at: '@'`). What the grammar itself refuses is answered in
  the parser's own words, at the furthest token it read (`unexpected 'RETURN'`, `the query ends where more is
  expected`, a character not read: `token recognition error at: '€'`; the words of ANTLR's errors were the Go
  service's, a choice of the project): the lexer reads the grammar's names, white space, dashes and arrow heads
  beyond ASCII (`unicode-ident`, `\p{Pc}` and `\p{Sc}`), an integer out of range of an int64 and a nested EXISTS or an
  EXISTS over a query are refused in Go's words.
  `ImportGraph` and the job `graph.import`: a snapshot is decoded as Go's `json.Decoder` with
  `DisallowUnknownFields` decodes it (`graph_core::godecode`: the scanner's syntax errors over the first value, the
  type errors and unknown fields with their struct and field path, the first kept while the decoding goes on, the
  errors of `Time.UnmarshalJSON` and `time.Parse` with the layout RFC 3339 stopping it); a time Go reads that chrono
  does not hold (an offset of 24 hours) or a value nested past 128 levels is still Go's.
- What Go answered of odd inputs, now Rust's too: an id that is no uuid on PostgreSQL (`ListTags`, `ListBaselines`,
  `DeleteTag`, the log of a change: pgx's text or Go's `mapErr`, `graph-store` `not_uuid`), a change naming a branch
  the store does not hold (`branch X: not found`), an item carrying a flow or a decision event (kept in its payload as
  Go keeps it, read only on a `flow` / `decision_point` item), a carried event whose payload is no UTF-8 (checked as
  `json.Valid` checks bytes, `godecode::valid`; on PostgreSQL the commit then fails as the outbox refuses it,
  `invalid byte sequence for encoding "UTF8"`, on SQLite it is stored as its text). The timestamps of the JSON
  answers are written as Go's `protojson` writes them (`goap_proto::wkt::Timestamp`: `Z`, 0, 3, 6 or 9 digits;
  pbjson-types wrote `+00:00`), and the proxy compares the form of a time (separator, zone) while it masks its value.
  `ExportChangeProvenance` reads the journal and model entries of the log as Go's `json.Unmarshal` reads them
  (`godecode::unmarshal`: the whole text checked first, unknown fields left, the type errors with Go's struct and
  field names), so an entry Go cannot read refuses the export with Go's `log entry N (type): …`.
- The rules of the organisation are no longer CEL: `graph-script` runs them as Go's Casbin and govaluate do
  (`casbin`: the model's matcher escaped and evaluated, its effect, the model functions with their arity errors and
  panics, `keyMatch*`, `keyGet*`, `regexMatch`, `ipMatch`, `globMatch`, `eval`; `govaluate`: its lexer, planner
  (precedence, mirrored stages, the arguments of a method accessor taking the rest of the expression), types and
  errors, a string reading as a date a number of seconds (`gotime`, the layouts of `tryParseTime`), a regular
  expression Go's RE2 (`goregexp`, translated to the `regex` crate with Go's refusals)). A stored rule `authz.Validate`
  refuses is left out of the organisation's rules as Go leaves it, the defaults applying while none is left. The
  answers are checked against Go's own Casbin: `contracts/authz` `TestRustCasesAreCurrent` writes
  `graph-script/src/casbin_cases.gen.json` (`GOAP_UPDATE_RUST=1`), rules and sets of rules with the answer and error
  of each request, which `abac` `answers_as_go_casbin` replays. The roles of `X-Goap-Roles` are split as
  `identity.FromHeaders` splits them, and a float64 printed as `%v` takes the exponent from 1e6 as Go's `fmt` does
  (`graph_script::go_float`; the JSON's 1e21 was used). The fold of a change's log for a write refuses nothing: Go
  reads past the `change.*` entries and the transitions alike.
- Fewer requests left to Go: a form's pattern compiled by Go's regular expressions (`goregexp`), its defaults
  checked as Go's widgets check them (text, number, date: `time.Parse(time.DateOnly, …)`, the bounds printed with
  `%g`), an algorithm's parameters coerced as `Param.Coerce` does (`strconv.ParseFloat`: hexadecimal, underscores,
  infinities; a regular expression Go's), the sample input of `RunAlgorithm` decoded with `encoding/json`'s errors,
  the coercion refusals of a definition read from JSON worded here (from YAML, where a number is an `int`, still
  Go's), domains that make no catalogue leaving the previous one in force as `typecat.Live.Reload` does (`ListTypes`
  answers the error, internal), and `MergeChange` answering the items it wrote whatever they hold.
- Rust decides where it cannot know Go's words: a CEL guard or criterion is refused at its path when it surely does not
  compile (it does not parse, in the Rust parser's words, or returns another type than a bool, `guard must return bool,
  got <type>` as cel-go says), and accepted when the checker does not follow it, an error left to its evaluation
  (`celcheck::judge`); a JavaScript algorithm is judged by QuickJS, the engine that runs it here; a definition read from
  YAML is judged as Rust reads it (coercions, form conditions, timestamps and unsigned integers); a request whose
  definition does not read as a domain is `invalid domain: …` in Rust's words, a snapshot Go's decoder would read but
  this one does not follow `parse snapshot: …`; an import failing on a change it cannot purge abandons it, as Go's
  does. Nothing the service serves answers `unimplemented` any more, so the split mode of the proxy is gone: `make
  perf-rust` runs mode `rust`, the comparisons (`shadow`, `compare`) still put the Go service beside it.
- The platform bootstrap (`graphsvc.Boot`, ADR 0071) is Rust's too: `goap-graph-rs bootstrap` boots once and exits
  (compose's `graph-bootstrap`), the service boots itself with `GOAP_GRAPH_BOOTSTRAP=1` or a memory store, and every
  start publishes the shipped domains of `GOAP_DOMAINS_DIR` not stored yet (`Domains::seed_domains`, Go's
  `SeedDomains`). The roots are `Tx::bootstrap` (`graph-core` `write/bootstrap.rs`, one applied change per namespace),
  the seeds `graph/boot.rs` in Go's order and transactions (access, built-ins, the adapters of the default unit,
  models, protected aliases, behaviours, sources, then the demo or the document repository of `GOAP_GRAPH_SEED`); the
  nodes the code states (policies, built-in MCPs and roles, the terse behaviour, the platform source, the model kinds)
  are read from `boot.gen.json`, written by `platform/devseed` `TestRustBootIsCurrent`. The models come from
  `GOAP_MODELS_CONFIG`, else `ANTHROPIC_API_KEY` (no Vault). Two bootstraps of an empty database, one Go and one Rust,
  leave the same tables and the same outbox (`goap-proxy diff-db`).
- A content graph too (`GOAP_GRAPH_SPACE=content`, `GOAP_PLATFORM_GRAPH_URL`, ADR 0154 §9): the domains are read
  from the platform graph's registry (`platform::Remote::catalog`, every `DOMAINS_TTL` or on its domain events), the
  organisation, the projects and the versions and roles of the methodologies at the head of main of the platform graph,
  read again when that head moves (`GetBranch`, then `GetBaselineGraph` / `ListViewNodes`). What was read travels with
  the session (`graph_core::platform::Platform`, `ReadTx::platform`): the snapshot, the directory, the structure checks
  of the guard and the roles of an operation take it instead of the store, as Go's `Graph.Directory`. It serves the
  graph service alone, bootstraps nothing and declares no user. The Go content graph reloaded its catalogue on a domain
  event from a client still holding what it read: it now drops it first. A Go platform graph driving a Go and a Rust
  content graph through the compare proxy leaves the same nodes, versions, links and outbox (ids apart). The models
  of the bootstrap read the Anthropic key in Vault as Go does (`goap/modelgw#anthropic_api_key`).
- The compose stack runs the Rust service: `graph-bootstrap` (`goap-graph-rs bootstrap`), `graph` and
  `graph-content` take the image `goap/rust:dev` (`make images` builds it with `goap/goap:dev`). The Go service stays
  the reference: the performance stack compares the two (`make perf-diff`), and `goap-dev` keeps the graph in process.
- Native crates, content not bytes: the Rust service no longer copies Go's libraries to answer byte for byte; it
  answers the same content, with the crate that does the work and its words where it words a refusal. The rules of the
  organisation run on `casbin` (casbin-rs, rules as rhai expressions: Go's model, its functions and the Go names of the
  principal and the resource, so the defaults and a rule of the common syntax decide as Go's; govaluate's own operators,
  `=~`, `??`, `in (…)` and the methods of the principal, are not read; `casbin_cases.gen.json` checks the decisions of
  the rules both read); patterns are `regex`'s; a CEL guard is judged by the `cel` crate's parser (no type check of
  its own); a definition is parsed by `serde_norway` and laid into the shape of `def.Domain` (`decode` over JSON
  values), the YAML of a domain and of an OKF front matter written by it (`graph_core::yaml`); a snapshot and the log
  payloads are read by `serde_json`. Gone: `crates/libyaml` (the workspace allows no `unsafe` any more),
  `graph-catalog` `yamlv3`, `graph-core` `goyaml` / `godecode`, `graph-script` `casbin` / `govaluate` / `gotime` /
  `goregexp` / `celcheck`, and `gojson`: JSON is written by `serde_json` (`graph_core::jsontext`), about 8,500 lines. Two values are
  compared as Go compares them (`jsontext::floats`: `1` and `1.0` equal, so a draft equal to its base is no
  modification), and the times keep the text Go stores, so that they sort alike. The paragraphs above on yaml.v3's
  words, govaluate, `celcheck`, `encoding/json`'s errors and Go's JSON bytes describe what this replaces. The compare
  proxy and `diff-db` compare content (ids paired, JSON texts as values, numbers by their value, an error by its code, its message apart as
  `message_differs`).
