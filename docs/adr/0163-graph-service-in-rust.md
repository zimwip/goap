# ADR 0163 — The graph service in Rust, behind a comparing proxy

**Status**: accepted; phase 1 implemented (the workspace, the store, the proxy, the perf targets) · **Date**: 2026-10

## Context

The graph service carries the load of the platform: every change, every commit and every read of a view goes through
it. The performance phases shaped it with a set of choices, each measured by `make perf`:

- **What a commit reads.** A baseline stores only its header; its state is a selection of the last commit of each node
  on its branch up to its order (ADR 0140, 0143). A commit and a merge read only the nodes they touch, in batches
  (ADR 0137 and addendum: `prefetch`, `BaselineVersions`, `LinkSetsOf`). The N+1 reads of a page are batched
  (`NodesAt`, change heads).
- **Links.** A version's links are a link set held as skip deltas of depth at most 16 (ADR 0141), written in batches
  of a thousand; a navigation hop reads its link types only, entering links by source.
- **Reads.** A request that only reads runs on a read-only pool, with no `BEGIN` / `COMMIT` on PostgreSQL, and runs
  again on the writer when it meets a write (SQLSTATE 25006, SQLITE_READONLY). `GetNode` answers a page of links.
- **Changes.** A change is a fold of its log (ADR 0153), its impact events carrying what they change (ADR 0142), one
  log entry per review or landing (ADR 0144); positions travel as watermarks (`X-Goap-Change-Seq`,
  `X-Goap-At-Least`).
- **Caches.** One bounded cache kind (ADR 0156): drafts 64 MiB, version links 32 MiB, headers 4 MiB, validations
  16 MiB, five minutes without a read.
- **Writers.** The writers of a tree of changes are serialized by an advisory lock on its root, then the branch lock
  (ADR 0127); the guardians judge in the transaction of the commit (ADR 0140).
- **Contracts.** Every read names its view (ADR 0157), reach filters it (ADR 0161), events leave through an outbox
  (ADR 0136).

Go reached the point where the remaining costs are the allocations of the folds and the decoding of the rows. Rust
removes the garbage collector from the hot paths and lets the type system carry invariants the Go code checks at run
time. The rewrite must not be a translation: only the behaviour of the RPCs and endpoints must stay the same.

## Decision

1. **A Cargo workspace beside the Go modules**, `rust/` (not in the `go.work`), generated from the same `proto/`:
   - `goap-proto`: the messages (prost, with pbjson for the protobuf JSON form) and per service a table of its methods,
     a server trait whose every method answers `unimplemented` by default, its router and its client, generated by
     `build.rs` with protox (no `protoc`); the descriptor set is exposed for the proxy.
   - `goap-connect`, `goap-ctx`: the Connect protocol (unary and server streaming, proto and JSON codecs, the error
     model, interceptors) over axum and reqwest.
   - `graph-store`: PostgreSQL (tokio-postgres, deadpool) or SQLite (rusqlite, compiled in: the one C of the build).
     Both keep a writer and a pool of read-only connections; `StoreError::is_read_only` sends a read that met a write
     to the writer. The migrations are the Go services' own files (graph, domain registry, smart tags), embedded and
     recorded in the same `schema_migrations` table (PostgreSQL by name under the advisory lock of the schema, SQLite
     by component and name), so either service starts on a database the other wrote.
   - `graph-service`: the binary `goap-graph-rs`, serving `GraphService`, `DomainService`, `SmartTagService` and
     `ImportService` with the environment of the Go service (`GOAP_HTTP_ADDR`, `GOAP_DB_DSN`, else
     `GOAP_SQLITE_PATH`, else a database in memory), `/healthz` and `/readyz`.
   - `goap-proxy` (below).
   The pure core (`graph-core`: views, folds, selection, link sets, the guard's obligations) comes with phase 2, free
   of I/O; the store is a trait per dialect with the SQL text of each, a reader and a write transaction as distinct
   types (a write cannot be asked of a reader), the tree lock a token the write operations take, the caches `moka`
   with the bounds of ADR 0156, the impact events one enum serialized to the bytes Go writes.
   Cypher reuses an existing parser (`decypher`, else `uni-cypher`); the scripts of the domains run on `boa` (no C)
   behind a `ScriptEngine` trait, a precompiled path (QuickJS as WebAssembly) left for later.
2. **A proxy in front of the graph services, deployed on its own**: `goap-proxy`, a Connect proxy that reads any method
   of `proto/` through the descriptors (no code per method). `GOAP_PROXY_MODE`:
   - `go`, `rust`: every call to one service, bytes passed as they are;
   - `split`: every call to the Rust service, replayed on the Go one when it answers `unimplemented` (HTTP 501, or a
     route it does not know): the two share one database. `/proxy/coverage` lists the methods called, who served them
     and those that still fall back; `POST /proxy/probe` asks the Rust service each method of the four services with
     an empty request (a test or perf environment only);
   - `compare`: every call to the Go service, which answers the client, and to the Rust one, each on its own database,
     one call at a time. Each side allocates its own UUIDs, so the proxy pairs the ids found at the same place of the
     two answers (lists matched by what their elements hold once the unknown ids and the times are blanked, map keys
     that are ids likewise; a short id, the eight first digits of a UUID as in `change-3013a15b`, follows its UUID),
     writes the Go ids of the next requests (body and headers) as their Rust twins, reads the Rust answer back in Go
     ids, masks the times and the fields of `GOAP_PROXY_IGNORE`, and gives a verdict: `same`, `order_differs`,
     `message_differs` (the soft ones), `differs`, `error_differs`, `undecodable`, `rust_unimplemented`. Every call is
     a line of `calls.jsonl` (verdict, both durations, differences, the ids that clash with an earlier pair, the bodies
     of a divergent call) in `GOAP_PROXY_REPORT_DIR`; `/proxy/report` writes `summary.json` and `ids.json`.
   - `goap-proxy diff-db --go <dsn> --rust <dsn> --ids ids.json` compares the tables of the two databases as
     multisets, once the ids are paired (the comparison's, then the rows one of a kind on each side) and the times
     masked.
   `/metrics` counts the calls per method and who served them (`goap_proxy_calls_total{service,method,served_by}`),
   the verdicts and the time of each side.
3. **The performance stack goes through the proxy.** `make perf` (mode go, `PERF_PROXY=0` without it), `make
   perf-rust` (`deploy/compose/perf.rust.yml`, mode `PERF_RUST_MODE`: split until the Rust service serves every
   method, then rust), `make perf-diff` (mode compare: both schemas dropped, the Go service on `graph`, the Rust one on
   `graph_rs`, goap-bench serial and seeded, then the report and `diff-db`; `PERF_DIFF_RUST=go` compares Go with Go).
   The image `goap/rust:dev` (`docker build --target rust`) holds both Rust binaries.
4. **Phases, one pull request each**: (1) the workspace, the store and its migrations, the skeleton service, the
   proxy, the targets; (2) the reads (views, `GetNode`, neighbourhoods, baselines, listings, queries); (3) the writes
   of the bench (changes, impacts, review, commit, merge, rebase, the domain registry); (4) everything else, then the
   Go service and the split mode leave the stack. Each phase is done when `make perf-diff` finds no divergence on what
   it serves.

## Consequences

- The comparison is measured before it measures Rust: Go against Go (`PERF_DIFF_RUST=go`) on 939 calls of the bench in
  lifecycle mode gave no divergence and no clashing id, and `diff-db` found the fourteen tables of the two databases
  the same. Lists the graph orders by id come in another order on each side: `order_differs` is soft.
- Both services read and write one schema; a migration lands in the Go directories and the Rust service embeds it on
  its next build. `TestSchemasAligned` keeps the two dialects aligned as before.
- The Rust service holds the same multi-database option as the Go one (PostgreSQL, SQLite); the Go service goes away at
  the end of phase 4, the proxy stays as the entry of the performance stack and of later comparisons.
- Not done yet: everything past phase 1.
